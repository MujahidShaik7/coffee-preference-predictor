# ☕ Coffee Preference Predictor

A full-stack web app that predicts which coffee style best matches you, using
a **trained scikit-learn classification model** — not hardcoded rules, not
randomness.

Answer 9-11 quick questions about your taste and habits → the model
predicts your best-match coffee (Espresso, Cappuccino, Latte, Americano,
Mocha, Cold Brew, or Filter Coffee) → you get a personalized result with a
confidence score, a "why this matches you" breakdown, and a coffee
personality.

---

## Features

- **ML-based prediction** — a real scikit-learn pipeline (preprocessing +
  classifier) trained on 2,500 synthetic-but-realistic preference profiles.
- **Interactive, single-question-at-a-time quiz** with progress bar, back
  button, and keyboard navigation.
- **Confidence score** shown honestly ("your strongest predicted match,"
  not a claim of certainty).
- **Personalized explanation** of why the result matches you, generated
  from your own answers (not fabricated feature-importance numbers).
- **Coffee personality** mapped to each result.
- **REST API** (`/api/predict`, `/api/health`) with full input validation.
- **Responsive, accessible UI** — works from 375px mobile screens up to
  desktop, with visible focus states and semantic HTML.

## Machine Learning

### Dataset
`data/coffee_preferences.csv` — 2,500 synthetic rows generated by
`ml/generate_dataset.py`. Each row is a person's answers to the
questionnaire, paired with a coffee label.

Labels are **not** assigned by deterministic if/else rules. Each coffee has
an "ideal profile" (target strength, milk, sweetness, bitterness,
creaminess, caffeine, temperature). For every synthetic person, the
generator computes a similarity score against every coffee's profile, turns
those scores into a probability distribution (softmax), and *samples* the
label from that distribution. This produces realistic overlap — e.g.
someone who's a strong Latte match might occasionally be labeled
Cappuccino, just like real people whose tastes aren't perfectly clean-cut.

### Features (11 questions)
`strength`, `milk`, `sweetness` (1-5), `temperature`, `bitterness` (1-5),
`creaminess` (1-5), `caffeine`, `time_of_day`, `flavor`, `experience`,
`previous` favorite coffee.

### Preprocessing
`ColumnTransformer` combining:
- `OneHotEncoder` for the 8 categorical features
- `StandardScaler` for the 3 numeric (1-5 scale) features

Preprocessing and the classifier are fit together in a single
`sklearn.pipeline.Pipeline` and saved as **one artifact** with `joblib`, so
the Flask API never has to hand-roll preprocessing logic.

### Algorithms compared
Logistic Regression, Decision Tree, Random Forest, and K-Nearest Neighbors
were all trained and evaluated on a held-out 20% test split (stratified by
label). **Logistic Regression** was selected as the best model based on
macro-averaged F1 score.

### Evaluation (held-out test set, n=500)

| Model               | Accuracy | Precision (macro) | Recall (macro) | F1 (macro) |
|----------------------|:--------:|:------------------:|:---------------:|:-----------:|
| **Logistic Regression** | **0.586** | **0.582** | **0.576** | **0.576** |
| Random Forest         | 0.546    | 0.527               | 0.487           | 0.489       |
| KNN (k=15)             | 0.468    | 0.454               | 0.422           | 0.430       |
| Decision Tree          | 0.436    | 0.400               | 0.402           | 0.389       |

~59% accuracy across 7 classes (vs. a ~14% random baseline) reflects that
the training labels were intentionally generated with realistic overlap
and noise rather than clean separability — the model is genuinely learning
soft preference patterns, not memorizing a lookup table. Full metrics and
the confusion matrix are printed by `train_model.py` and saved to
`models/metrics.json`.

Re-running `ml/train_model.py` prints the full comparison, confusion
matrix, and classification report every time.

## Installation & Setup

```bash
# 1. Create and activate a virtual environment
python -m venv venv

# macOS / Linux
source venv/bin/activate
# Windows
venv\Scripts\activate

# 2. Install dependencies
pip install -r requirements.txt

# 3. Generate the dataset
python ml/generate_dataset.py

# 4. Train the model (compares 4 algorithms, saves the best one)
python ml/train_model.py

# 5. Run the app
python app.py
```

Then open **http://127.0.0.1:5000** in your browser.

## API Reference

### `GET /api/health`
```json
{ "status": "ok" }
```

### `POST /api/predict`
Request body:
```json
{
  "strength": "medium",
  "milk": "high",
  "sweetness": 4,
  "temperature": "hot",
  "bitterness": 2,
  "creaminess": 5,
  "caffeine": "medium",
  "time_of_day": "morning",
  "flavor": "caramel",
  "experience": "sweet & creamy",
  "previous": "latte"
}
```

Response:
```json
{
  "prediction": "Latte",
  "confidence": 0.87,
  "description": "...",
  "personality": "The Smooth Explorer",
  "personality_description": "...",
  "why_this_matches_you": ["...", "..."],
  "top_matches": [{"coffee": "Latte", "confidence": 0.87}, ...]
}
```
All fields are validated server-side. Invalid or missing fields return
`400` with a plain-English `error` message; server issues return `500`/
`503` — no stack traces are ever exposed to the client.

## Limitations

- The dataset is synthetic, not collected from real users — it encodes
  reasonable domain assumptions about coffee preferences, not verified
  consumer behavior.
- ~59% accuracy across 7 overlapping classes is solid for this kind of
  soft-preference problem, but it is not a claim that any prediction is
  "correct" — it's the model's best-supported guess, which is exactly how
  the UI frames it.
- This is a portfolio/academic project and uses Flask's built-in dev
  server; for production use, run it behind a proper WSGI server (e.g.
  gunicorn) as noted in the console warning.
